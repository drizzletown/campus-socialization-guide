读者试用与认知可用性检验方案（v1.2）

用于组织自愿阅读与改稿，不表示本读物已经得到教育效果验证。这个方案检查的是读物能否帮助读者分析具体事件，不测试人格、社交水平或心理健康。

一、试用目标

围绕四个可观察的问题开展审阅：（1）学生能否区分事实、推测和情绪体验；（2）是否能够提出两种以上合理解释，而不急于给人贴标签；（3）能否找出谁具有改变某项限制的责任与权限；（4）是否能提出与现实条件匹配、风险适当、允许调整的行动方案。另检查是否出现误导性归因、角色偏见和无法实施的建议。

二、建议的三轮流程

第一轮，专家与学生代表的文本审读。 邀请熟悉学生发展、课程教学、学生事务、权益保障的审阅者，连同不同年级、专业的学生代表，逐章标出术语难点、规则缺口、危险建议和失真的场景。每条意见注明章节、原句、修改理由及所需证据。

第二轮，情境化认知试读。 组织自愿读者，先展示一项陌生情境并让其说明初始判断；然后阅读对应章节，再分析一项条件发生改变的相似情境。重点观察解释是否更细、是否把责任错误地全部推给学生，以及行动步骤能否实施。适当使用访谈，询问哪些词语不能理解、为什么选某行动。前后不同情境不能当作严格因果实验。

第三轮，真实场景可用性检查。 允许读者自选一个低风险日常事务，例如课程答疑、共同作业或活动报名，尝试使用工具卡。只收集自愿提供的、去标识化的问题类别、采取的行动类型及对工具的意见；不得强制交出私人聊天、病历、具体成绩、他人姓名或组织机密。危险和法律争议应转交正式支持渠道，不纳入普通练习任务。

如果计划将试用数据用于学术研究或公开发表，应事先核对所在机构的研究伦理审查、知情同意、数据保存与未成年人参与规则。

新增：网站情境分流可用性测试

在阅读之前，让自愿试读者选择一项自己没有亲历过的低风险情境，进入“情境分流”页。观察其能否在不输入私人资料的前提下找到相关问题、识别两条分支之间的关键差别、判断何时需要正式组织回应；再请其到相应章节与工作卡尝试提出下一步。记录无法识别的词句和找不到的入口，但不要追问私人经历。这是内容可用性检查，不是临床筛查或社会化成熟度测量。

三、六项认知试读题（均为编写的情境）

情境A：科研兴趣相同，限制却不同

甲能独立完成基础实验，但这学期课程与竞赛已占满时间；乙时间充足，却不清楚报名要求。两人都没有提交申请。请分别分析甲、乙的主要限制；各应先向谁核查什么；有哪一种不必立刻加入项目的合理行动？

观察要点： 是否区分时间承诺、能力准备与信息入口；能否承认暂缓是有理由的选择。关联第05、26章。

情境B：团队成员“没动手”

某小组的成员丙未提交代码，但他从未收到仓库权限；丁已经获得权限，却不能解释验收标准。组长说两人都不负责。你应当先核实哪些事实？分别由谁改变哪种条件？

观察要点： 能否分清资源授权与规则学习，并识别组长、任课教师的责任。关联第09章。

情境C：宿舍作息争议

甲要求23点以后安静，乙经常在23:30参加有出勤要求的线上实验答疑。双方尚未看过宿舍管理规则。提出两个可行安排，并说明如果出现持续辱骂或威胁应该怎样改变处理路径。

观察要点： 是否考虑真实任务、公共规则、双方同意和安全升级。关联第11、18章。

情境D：校内奖助与个人隐私

学生有经济困难，但申请人被要求在私人社交群公开家庭经济详细信息，且未提供正式政策链接。应如何核查申请要求？谁负责说明数据用途？有什么不暴露隐私的申请方式？

观察要点： 是否区分正式资助审核和无依据的私人披露要求；是否能找到制度入口。关联第13、41、44章。

情境E：课程AI辅助

某课程要求独立提交程序，但关于AI的课堂规定不明确。同学分享了可直接运行的代码，还附带未公开的项目数据。请决定哪些步骤必须停止或核查，怎样确认自己的独立能力，哪些事项需要教师澄清。

观察要点： 是否重视课程规则、数据授权、独立验证，不把“可运行”视为全部证据。关联第10、34章。

情境F：实习与权限

实习生接到一项数据分析任务，被要求将含客户联系信息的文件发到自己的私人邮箱，以便在家完成。该学生担心拒绝影响考核。提出能兼顾任务目标与信息安全的替代方式；确认谁有权限批准数据处理。

观察要点： 是否识别保密、安全和考核权力；能否提出在授权环境完成工作等替代路径。关联第30、35章。

四、阅读反馈记录格式

建议使用非量化记录，避免计算“社会化成熟度”。

项目 观察与修订意见
情境编号与章节 如情境B／第09章
读者初始解释 记录主要观点，不要求私人经历
阅读后对照分析 哪些事实、解释、权责和行动发生变化
容易误解的语句 保留具体原句
不可操作的步骤 说明当地学校缺少的入口或资源
安全或公平性问题 是否把制度障碍错误归因给学生
建议修订 改写内容、增加例证或删去建议

分析维度（仅用于评价文本，不是评价个人）： 事实核实是否充分；解释是否能区分不同成因；责任归属是否准确；行动是否可实施；是否尊重拒绝、隐私与安全。每项可记录“清楚／待澄清／有风险”和对应例证，不汇总为个人分数。

五、发布前必须核验的风险和合规事项

  • 校内评价、学籍与奖助资格按发布地、本校当年的正式规则核对。
  • 科研伦理、作者署名、个人信息处理按相关机构和学科规范核对。
  • 学生心理危机、骚扰、暴力与诈骗相关章节由熟悉转介和安全流程的审阅者检查。
  • 不公布真实学生案例的身份线索，不上传群聊、导师通信或受助者个人信息。
  • 公众反馈通过 GitHub Issues 时，仅描述可公开的文本问题，具体危机求助不通过 Issue 处理。

六、何时能够宣称“有效”

完成一次阅读不等于产生教育效果。需要预先界定评价指标、对照材料与数据处理方法，并在符合伦理要求的条件下开展独立实证研究。未经研究，只能说“内容经过试读修订”或“读者报告某一工具有帮助”，不能据此推断模型产生了因果作用。

v1.3 学生视角试读任务（待实施，不代表已经完成试验）

试读应为自愿参与、可以随时退出，不请求提供亲密经历、医疗、身份或未公开成绩信息。使用虚构材料，不让学生为了测试进入真实的高风险场景。

七项读者任务

  1. 课程求助： 给定“考试未掌握”和“提交版本被评分系统遗漏”两种文本情境。请读者选择应先复习、求助还是申请复核，并说明依据。
  2. 宿舍冲突： 比较首次出现的夜间噪声与反复威胁，询问什么时候不应继续单独协商。
  3. 科研参与： 给出公开招募和无许可导出研究数据的情境，观察是否识别训练与伦理责任的差异。
  4. 社团负责人： 给出财务审批权缺失的活动，询问学生可以决定和必须提交审批的事项。
  5. 亲密关系： 比较约定联络时间与强迫交密码，检验能否区分协商与控制，并保护自主选择。
  6. 求职： 比较技能匹配不足与招聘方要求缴费的情境，观察是否采用不同处理。
  7. 权益保护： 分别处理普通评分申诉与紧急人身风险，检验是否知道何时跳过普通申诉流程。

记录方式和判断指标

可记录（1）读者能否找到相关页面，（2）能否指出两条竞争性解释，（3）能否提出一个受约束、可实行的动作，（4）是否识别由组织或专业机构承担的责任，（5）在高风险条件下是否避免直接对抗和泄露隐私。不要只问“是否觉得有用”，也不以某一个答案给学生贴成熟度标签。

请试读者指出页面中不理解的词句和难以使用的步骤；反馈按“有证据的混淆—修改建议—复查任务”整理，作者不能将虚构任务的结果冒充真实大学生活中的因果效果。

v1.4 后续真实学生试读执行表（待实施）

本文件是计划，不意味着已经邀请任何真实学生。请使用虚构情境，避免要求披露成绩、恋爱隐私、病史、聊天记录及他人姓名。

建议流程

  1. 让自愿读者用自己的自然语言描述给定虚构任务；记录查询词及页面命中情况时获得同意，不与真实身份绑定。
  2. 未给提示前观察其能否找到专题或章节，遇到困难允许跳转目录。记录“成功找到/寻路困难/错误跳转”，不要评分个人社会化程度。
  3. 阅读后请其分别指出事实、可能解释、组织责任、下一步和安全边界；让其解释为什么某个条件变化会使行动方案不同。
  4. 询问原文哪一处最难理解、哪一步最不可能执行、谁有权限提供该帮助。
  5. 将反馈编码为“搜索漏召回、错误分流、术语困难、行动缺口、制度不适用、安全风险、重复信息”；修订后再以新题复查。

不可做的事

  • 不让学生真实去举报、对抗施压者或从事危险实践作为试验项目。
  • 不将表格交给学校用于人格排名或社会化成熟度考核。
  • 不承诺绝对匿名或绝对保密；如开展正式研究须明确告知实际数据流程。
  • 不把参与者的主观“感觉有帮助”直接当成教育效果因果证据。

发布前核验

核对本校正式申诉、学业、学生资助、住宿、实验室和实习规定，并交由拥有专业责任的人员确认安全与转介文字。
